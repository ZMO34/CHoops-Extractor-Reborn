# Conference realignment, fixtures and tournaments

Read-only CH2K8 PS3 native research. Roster membership repair is not a schedule
generator, and the stored capacity of 100 conference members is not proof that
every conference size works with the original Legacy scheduling systems.

## Why realignment can break scheduling

The roster contains a separate match table: directory count +0x30, pointer +0x34,
20-byte records. Native accessors `0x1BC2E4` / `0x1BC304` read that directory and
stride. Each record has a raw game key and signed home/away school indices at +4
and +6. Calendar encoding and remaining packed flags are preserved, not guessed.

The inspected stock roster has 5,523 allocated records: **4,523 nonblank fixtures
and 1,000 all-zero reserved rows**. Blank rows are not self-matches or certified
available scheduling capacity. Conference moves update membership/backlinks but
leave these fixture bytes unchanged. A new member therefore keeps its old opponents
unless a separate, proven schedule transformation is performed.

Native rollover `0x5A5190` maps teams through conference lists, then calls
`0x5ACDB4` and `0x5B7E84` to transform existing scheduling state. That is not proof
of a general round-robin generator for newly enlarged conferences. Membership
cardinality changes need a valid mapping and calendar, not just new names.

Two auxiliary conference pointer lists also matter. Sorting routine `0x73E654`
builds the ranked list at +0x874 and copies its old contents to +0xA04. Rollover
uses both lists. `0x73D8BC` and `0x73DA9C` rebase all 100 pointers in each list
during serialization/deserialization. They must not be filled with membership
order or overwritten as if they were unused padding. The diagnostics do not
pretend that editing those lists alone repairs scheduling.

## Tournament omissions and native special cases

- Conference +0x1A is the tournament route, +0x1C the qualifier count and +0x1E a
  calendar offset used by the native scheduling path.
- Event registration `0x73E884` explicitly skips route **96**. Stock Ivy League
  and Independents use 96 and have zero entrants; adding members or setting an
  entrant count alone cannot make their event run.
- The runtime tournament table has 97 entries of stride 0xAC. Active conference
  routes sharing an entry are suspicious: constructor `0x58F74C` initializes only
  an uninitialized entry. No route is silently reassigned by the editor.
- Conference entrant IDs occupy row +0x88..+0xA7: **16 u16 slots**, immediately
  before the count at +0xA8. `0x58F74C` copies the supplied entrant count without
  clamping it. Seventeen overwrites the count; more can reach the next entry.
- `0x73F5FC` selects qualifiers from the ranked member list using +0x1C. A count
  larger than membership can read beyond populated qualifiers even if it is ≤16.
- Ivy conference index **14** is special in champion provider `0x73E534`: it uses
  the regular-season standings leader. Independents index **13** is excluded from
  a conference champion processing path in `0x73F5FC`. Renaming these conference
  rows does not remove the executable's special behavior.
- Standings preparation has an index <32 path and event registration loops 39
  conferences. New indices are not automatically a supported expansion route.

A 20-member conference with a 16-team qualifying tournament is different from a
20-entrant tournament. The first is not blocked by the new bracket guard; it still
requires valid fixtures, seeds and timing. The second needs native bracket/storage
changes. The editor now rejects explicit entrant edits above **min(members, 16)**
through its shared backend, including CSV/import callers, and bounds its GUI input.
Existing imported values are diagnosed rather than silently rewritten.

## Diagnostics and remaining implementation

Open **Recruiting diagnostics… → Scheduling / tournaments**. It shows current
members, fixture counts per member, tournament route/entrants and specific
diagnostics. Counts use current membership, not an invented interpretation of
unmapped match flags. Uneven counts alone can be legitimate. Missing fixtures,
duplicate links, oversized qualifiers and route conflicts are reported separately.
Special policies are described even when they are intentional stock behavior.

CLI: `inspect-legacy-schedule ROSTER_FILE OUTPUT.json`. Reads supported roster
wrappers and preserves both inputs and unknown game bytes. Reports stay separate
from game-data CSV export. The realignment dialog now states that fixtures and
tournament registration are not regenerated by a membership move.

No complete modern-alignment repair or extra tournament registration is claimed.
Remaining work: inspect the affected edited roster, establish calendar and fixture
generation contracts, valid seed/date templates for changed membership, a complete
route allocation plan, and intentional handling of native index 13/14 policies.
The owner's specific failing roster was requested but was not available during
this pass; supplied stock data and synthetic membership changes were inspected.
No EBOOT edits or gameplay tests were performed.
